# Лабораторная работа №01. Модель памяти и атомарные операции

Каркас решения. Логика вынесена в библиотеку, рядом — `harness`
и тесты. Проект уже собирается и отвечает на `info`.

```bash
docker build -t pp-lab .
docker run --rm pp-lab info
```

## Что менять нельзя

| Что | Почему |
|-----|--------|
| имя исполняемого файла `harness` | по нему работа запускается при приёме |
| одна строка JSON на команду в stdout | вывод разбирается машиной |
| код возврата 0 при успехе | ненулевой код — провал проверки |
| расположение файлов из таблицы ниже | по нему определяется язык проекта |

Диагностику, замеры и всё, что печатается «для человека», выводите в
stderr: на разбор вывода она не влияет.

## Обязательное расположение файлов

| Язык | Файлы |
|------|-------|
| C++ | `CMakeLists.txt`, `include/**/*.hpp`, `app/harness.cpp`, `tests/*.cpp` |
| Rust | `Cargo.toml`, `src/lib.rs`, `src/bin/harness.rs`, `tests/*.rs` |
| Go | `go.mod`, `cmd/harness/main.go`, `**/*_test.go` |

Плюс `README.md` и `Dockerfile` в корне — для всех языков.

Логика решения намеренно вынесена в библиотеку (`pp_lab` / `pp_lab` /
`solution`), а не в `main`: только так её видят и `harness`, и тесты.
